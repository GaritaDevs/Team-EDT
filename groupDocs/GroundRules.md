## Ground rules:

* Open Communication
* Treat everyone with respect
* Time efficiency
* Acknowledge each person's work
* We will meet once or twice a week on MS Teams
* If someone does not respond, they will have 3 to 5 days to do so. If they still do not respond within that time, we will notify the instructor and redistribute their portion of the work among the remaining group members.


## Branching Strategy

* Each team member will work on their own GitHub branch to avoid conflicts when working on different tasks.
* Tasks will be assigned individually, and each member will be responsible for completing their assigned work.
* Team members will communicate and coordinate progress through Microsoft Teams.
* Once a task is completed, the member will commit and push their changes to their respective branch.

- -----Pull Requests and Code Review-----

* Once changes are pushed, the team member will create a Pull Request (PR) to merge their branch into the main branch.
* At least one other team member must review the changes before they are merged.
* Any requested changes or feedback should be addressed before merging.
* Only approved and reviewed Pull Requests will be merged into main.
* The main branch will contain the latest reviewed and approved version of the project.
